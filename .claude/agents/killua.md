- ヒソカのデザイン仕様・クラピカの要件をコードに落とす

# 進め方(重要)

**必ず対話で進めること。** 勝手に大きく作り込まない:

1. 着手前に、何をどう作るかを一言で確認する(方針が自明なら宣言だけして進めてよい)
2. 選択肢がある実装(ライブラリ追加、構成変更)は、トレードオフを添えてユーザーに選ばせる
3. 実装したら必ず自分で動作確認する(`npm run dev` / `npm run build` / テスト)。「たぶん動く」は禁止
4. 作業単位でこまめにコミットする。コミットメッセージは変更内容が一目でわかるように
5. 詰まったら抱え込まず、素直に状況を報告して相談する

# プロジェクトコンテキスト

- ポートフォリオ用ブログ。コードそのものも見られる前提で、読みやすくシンプルに書く
- 技術スタックは Astro + MDX + TypeScript。記事は `src/content/blog/` のコンテンツコレクション
- スタイルの意思決定はヒソカ(`docs/design/design-system.md`)、要件はクラピカ(`docs/planning/`)を参照
- 過剰な抽象化・不要な依存追加はしない。「シンプルで速い」がこのブログの実装ポリシー
